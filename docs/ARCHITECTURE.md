# 架构详解

## 1. 设计目标

| 目标 | 手段 |
| --- | --- |
| **可解释**：每一步结论都有指标或文档支撑 | 四阶段链路显式拆分，阶段间传递结构化产物 |
| **可扩展**：加指标不改代码 | 指标目录 + 脚本契约，Function Schema 自动生成 |
| **可降级**：缺组件也能跑 | Redis / Embedding / 采集三重降级 |
| **可复用**：经验不随人走 | 故障指纹 + Redis 倒排，相似故障毫秒级复用 |

## 2. 数据流

```
用户提问
  │
  ▼
[① 意图理解] LLM → JSON{fault_type, hosts, time_window, urgency}
  │                 解析失败 → 规则兜底
  ├────────────────────────┬────────────────────────┐
  ▼                        ▼                        ▼
[②a 知识检索]        [②b 历史故障]          [③ 指标采集]
向量+BM25+RRF        Redis 指纹索引         Function Calling
  │                        │                 并发 + 超时熔断
  └────────────┬───────────┴────────────────────┘
               ▼
        [③ 指标分析] USE 方法：使用率 / 饱和度 / 错误
               │
               ▼
        [④ 方案生成] 根因 + 置信度 + 分级命令
               │
               ▼
        结构化诊断报告 → 用户确认 → [save_incident] 入库沉淀
```

## 3. 关键设计决策

### 3.1 为什么用 Dify 编排而不是纯代码 Agent

- Prompt 与链路调整是高频动作，交给可视化画布后，运维同学也能改；
- 多模型切换（GPT / DeepSeek / Qwen）只需改一个下拉框；
- 但**工具执行不放进 Dify**，避免 Agent 平台成为性能和安全瓶颈 —— 采集能力以 HTTP 服务独立部署，可压测、可鉴权、可复用给其它系统（未来的 MCP Server 也复用同一套）。

### 3.2 为什么混合召回而不是纯向量

| query | 纯向量 | 纯 BM25 | 混合 |
| --- | --- | --- | --- |
| "机器卡" | 漂移（语义泛） | 命中（关键词） | 命中 |
| "处理器使用率过高" vs 文档 "CPU 飙高" | 命中（语义近） | 不命中（无词重合） | 命中 |

RRF 融合的额外好处：不要求两路分数同量纲，无需调权重即可稳定工作。

### 3.3 为什么指纹 + 语义双路查历史

- 指纹（故障类型 + 主机角色 + 指标分桶）**精确、极快**，同一台机器反复出同类问题时直接命中；
- 语义/关键词兜底**覆盖表述不同但本质相同的故障**；
- 先精确后模糊，兼顾性能与召回。

### 3.4 三重降级设计

| 组件 | 不可用时 | 影响 |
| --- | --- | --- |
| Redis | 切换为进程内字典 | 多实例间不共享，单实例功能完整 |
| Embedding API | 降级为 hash 向量 | 语义召回质量下降，BM25 仍可用 |
| 采集脚本（非 Linux） | mock 数据 | 用于演示/开发，生产置 `COLLECT_MODE=real` |

这样保证：任何人在任何机器上 `git clone && pip install && pytest` 都能跑通。

## 4. 安全边界

1. **主机白名单**：`COLLECT_ALLOWED_HOSTS`，默认只允许 localhost；
2. **超时熔断**：单指标默认 10s，超时返回 `ok=false`，不阻塞整条链路；
3. **命令分级**：`rm -rf` / `kill -9` / 重启服务等危险操作强制输出到「需二次确认」章节；
4. **只读优先**：默认采集脚本全部为只读命令，不含任何修改操作；
5. **SSH 传输**：远程采集通过 `ssh bash -s` 传脚本内容，目标机无需任何预置文件。

## 5. 性能考量

- 指标采集并发执行（`asyncio.gather` + `to_thread`），18 个指标整体耗时 ≈ 最慢单项；
- 指标结果缓存 60s，Agent 多轮追问时不再重复采集；
- RAG 索引服务启动时预热，避免首请求抖动；
- 向量全量常驻内存（40 条语料约 0.2MB），无外部向量库依赖；语料量级上万后再替换 FAISS/Milvus。
